# Documentation maintenance instructions

These instructions apply to this documentation directory. They do not grant
permission to deploy, send messages, or change account settings.

- Read the ordered index and relevant implementation before editing a document.
- Describe implemented behavior separately from plans and unverified claims.
- Preserve existing application files during documentation-only tasks.
- Keep names, routes, environment variables, and commands consistent with code.
- Never include passwords, access tokens, client secrets, private recordings,
  or database contents in documentation.
- Do not claim a model works merely because a file exists or HTTP returned 200.
  Distinguish strict-loading checks, sample predictions, and benchmark accuracy.
- Identify public ProSDD ASVspoof2019 separately from the private epoch-4 model.
- Preserve relevant limitations: personal OAuth login and visual browser checks
  have not been completed by the agent where permissions prevented them.
- Verify relative document links after additions or renames.

Project implementation guidance and acceptance criteria are recorded in
PRD.md, ARCHITECTURE.md, AUTH_SECURITY.md, and TESTING.md.
